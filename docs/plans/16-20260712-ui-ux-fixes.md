# Исправление некорректного UI/UX

## Overview

Issue #16 — накопительный список UI/UX-замечаний по приложению. Первая партия (из комментария к issue) содержит 8 пунктов на двух участках:

**Страница «Источники»:**

- кнопка «Добавить» не на одном уровне с полем ввода;
- маска модального окна удаления источника слишком тёмная;
- кнопки «Удалить»/«Отмена» в модальном окне не на одном уровне;
- нет иконки источника слева от названия;
- кнопка «Добавить» в тёмной теме слишком светлая — режет глаз.

**Хедер сайта:**

- переименовать в «Curio» (полный ребрендинг product-facing текстов; favicon добавится отдельно, позже);
- выровнять ссылку «Источники» на один уровень с заголовком;
- клик по заголовку должен открывать главную страницу.

Каждое замечание фиксируется отдельным коммитом со ссылкой на issue (см. «Формат работы» в issue #16) — этот план разбивает партию на задачи вдоль тех же границ.

## Context (from discovery)

- **Web**: хедер продублирован один в один в `apps/web/src/app/(dashboard)/layout.tsx` (заголовок — plain `<h1>`, не кликабелен) и `apps/web/src/app/admin/layout.tsx` (заголовок уже `<Link href="/">` — паттерн для копирования). Навигация — общий `apps/web/src/components/main-nav.tsx`.
- Форма добавления источника — `apps/web/src/app/(dashboard)/sources/add-source-form.tsx`: кнопка выровнена вручную (`className="mt-6"`) относительно `TextField` из внешнего пакета `@ssortia/shadcn-zod-bridge`.
- Диалог подтверждения — общий shadcn-компонент `apps/web/src/components/ui/alert-dialog.tsx` (`AlertDialogOverlay` — `bg-black/80`; `AlertDialogFooter`/`AlertDialogCancel`/`AlertDialogAction`), используется только для удаления источника (`sources-list.tsx`), но правки в компоненте затронут любой будущий `AlertDialog`.
- Кнопка `variant="default"` (`apps/web/src/components/ui/button.tsx`) в тёмной теме легитимно инвертируется по shadcn-конвенции (тёмный фон в светлой теме → светлый в тёмной), цвета заданы CSS-переменной `--primary`/`--color-primary` в `.dark` (`apps/web/src/app/globals.css`).
- **Источник данных для favicon**: `Source` (Prisma) сейчас хранит только `type`/`url`/`title`/`lastFetchedAt` — реального favicon-URL нет. Существующий паттерн для внешних фетчей — «gate»-сервисы (`rss.gate.ts`, `telegram.gate.ts`, ADR-009): транспорт + парсинг без доменной логики, исключений не бросают, возвращают `null` при неудаче. `telegram.gate.ts` показывает точный образец — `fetch()` + `cheerio` для HTML-скрейпинга.

Упоминания «NexST Template» в `README.md`, `docs/DOCUMENTATION.md`, `docs/issues.md` — это ссылка на исходный шаблон-скаффолд, а не название продукта, их трогать не нужно.

## Solution Overview

- **Favicon**: новое поле `Source.faviconUrl` (nullable). При добавлении RSS-источника `SourcesService.addSourceByType` дополнительно вызывает `FaviconGate.fetch(origin)`, где `origin = new URL(canonicalUrl).origin` — **домашняя страница сайта, а не URL RSS-фида** (фид отдаёт XML, `<link rel="icon">` там искать бессмысленно). Гейт скачивает HTML `origin`, ищет `<link rel="icon"|"shortcut icon">` и резолвит его в абсолютный URL; при отсутствии тега — fallback на `${origin}/favicon.ico`; при сетевой ошибке/невалидном HTML — `null`. Фетч выполняется **до** открытия `$transaction` (рядом с существующим `fetchFeed()`), чтобы не держать сетевой запрос под открытой БД-транзакцией. Для TELEGRAM-источников `faviconUrl` не фетчится (у Telegram-каналов нет классического favicon) — фронтенд показывает иконку по типу. На фронте `<img>` с `onError` дополнительно откатывается на иконку по типу, если сохранённый URL перестал быть доступен.
- **Хедер**: общий компонент `apps/web/src/components/header.tsx`, используется в `(dashboard)/layout.tsx` и `admin/layout.tsx` вместо продублированной разметки — устраняет дублирование и чинит оба layout'а одним изменением (админский хедер уже был кликабельным `<Link>`, дублирование убирается в его пользу).
- **Тёмная тема**: `--primary`/`--color-primary` в блоке `.dark` (`globals.css`) притемняется — глобальная правка design-токена, затрагивает все `variant="default"` кнопки приложения одинаково (а не точечный override одной кнопки).
- **Остальные пункты** — точечные Tailwind-правки в существующих компонентах без изменения структуры.

## Technical Details

- Prisma-миграция: `faviconUrl String?` в модели `Source` — `pnpm --filter @repo/api db:migrate`.
- `FaviconGate` — новый класс рядом с `rss.gate.ts`/`telegram.gate.ts`, тот же контракт (`fetch(): Promise<string | null>`, не бросает исключения, логирует `warn` при неудаче через `Logger`).
- `SourcesService.addSourceByType` — favicon фетчится только в ветке создания нового `Source` (не при переиспользовании существующего — `faviconUrl` уже сохранён с первого раза) и только для `type === 'RSS'`; фетч выполняется **до** `this.prisma.$transaction(...)` (аналогично существующему `fetchFeed()`), результат передаётся в `data.faviconUrl` внутри транзакции — сетевой запрос не должен выполняться под открытой БД-транзакцией.
- `SourceSchema` (`packages/types/src/sources.ts`) и `SourceDto` (`apps/api/src/sources/dto/source-response.dto.ts`) получают `faviconUrl: string | null`.
- Фронтенд: иконка по типу — `Rss` (RSS) / `Send` (TELEGRAM) из `lucide-react` (уже используется в проекте, см. `Trash2` в `sources-list.tsx`).
- Хедер: `Header` принимает `role` (для `MainNav`) и рендерит `<Link href="/">Curio</Link>` + `MainNav` + правую часть (тема/email/выход) — переносится как есть из текущей разметки `admin/layout.tsx`, с точечной правкой выравнивания (после визуальной проверки — например, единый `leading-none` или `items-baseline` вместо `items-center`, если исходная причина в line-height разных размеров шрифта).
- Диалог: `AlertDialogOverlay` — `bg-black/80` → `bg-black/50` (или другое значение по итогам визуальной проверки, но заметно светлее); `AlertDialogFooter`/кнопки — проверить фактическую причину рассинхрона по вертикали в DevTools перед правкой (код `buttonVariants` для `Action`/`Cancel` выглядит идентичным по высоте — возможно, потребуется явный `items-center` на футере).
